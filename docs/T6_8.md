# T6.8：保留 Live 基底，新增 Reference 180 秒 Live 補位

Profile `regime_target6_8_v1`，tier `REGIME_T68`，package `6.8.0`。
父版本 T6.7c，承接主分支 PR14 的 HTTP deadline、持久 cooldown、evidence容量及可信 release verifier 修正。

## Live 規則

八路 Live：first DOWN、first UP、stall DOWN、原 C DOWN、continuation Original、C-UP 前趨勢鏡像、淺回撤，以及新增 Reference 180 秒補位。T6.7c 的 core-first routing、Original依賴、C的0.65下限、cap、有效期限、2秒增量quote TTL、1/2/3U、單市場一次BUY與共用風控均沿用。前七路的執行時窗維持124–136秒；拒絕、逾時或資料缺失不會授權補位。

新增 `reference_180_mid` **直接接入Live**，經共用worker的官方曝險核對、風控、atomic claim、intent及HTTP邊界送單。既有Reference與外部先行兩路保留為基準Shadow。固定每20run績效只計官方實際BUY與核對完成的settlement；模型候選、檢查點與兩路Shadow不進Live PnL或MDD。

## Reference檢查點

每個正式verified admission的市場記錄60／120／180／240秒各一次。每次用當時可見的新鮮盤口、同generation spot歷史與原模型；保留模型版本、as-of概率、模型輸入摘要、完整盤口、每側候選／執行／成本與否決原因。未通過、缺資料及超過1500ms grace的檢查點也明示；第一份記錄不可被較晚成功覆盖，不拿未來資料補過去。

`t68_reference_checkpoints` 位於 feature DB，獨立於短期spot／book保留期限。單payload沿用64KiB限制；檢查點資料總量32MiB、最多20000列，低於128MiB磁碟reserve時停止新觀測。只對檢查點寫入設限制，不修改共享DB的page／WAL限制，不刪除既有策略決策或交易歷史。耗盡後明示缺資料，不製造通過或收益。

儲存概率與模型摘要能重播當時凍結的成本／候選篩選；不宣稱可以由摘要重建所有原始tick或測試任意新的概率模型。

## 180秒 Live 補位

只允許第180–181.5秒選定新Reference候選：

- 原核心guard確實verified且empty，凍結於124–126秒，所有feature、loop、topic、UP ID、起止、unit及fee身分一致。
- 原Live決策未selected；沒有任何該市場claim／intent（包括REJECTED）、BUY持倉或UNKNOWN。缺schema／證據不當作零曝險。
- 當時模型EV每U至少0.03、買價每股加0.02後EV至少0.005，並保留原模型的cap與深度要求。
- **含費成本** `cash / net_shares` 在 `[0.40,0.65)`。這是Reference的損益兩平成本區間，不是原C的ask下限。

滿足上述才凍結 `reference_180_mid` Live決策；方向、概率、unit、fee與signal保持不變，經新盤口重新核對含費成本區間、深度及凍結概率下每U至少0.005 EV後送單。首次補位評估或後續執行遭否決的結果持久保存。有效期限為選定後2秒，最晚183.5秒；不重新選向、不重送已拒絕意圖，也不使用「後來有無成交」決定當時可否補位。第240秒只收觀測證據，不開第二補位時窗。

## 診斷與報表

T6.8的bridge拒絕理由使用固定code，區分盤口時鐘、深度、價格區間、Original EV、身分、fee、features及資料庫不可用；不複製任意exception字串。post-claim保留既有REJECTED行為，同時記錄具體admission理由／否決分類；本版不增加重送、不延長TTL、不放寬HS或cap。

T6.8獨立policy fingerprint、`t68_decisions`、`t68_shadow_*`、loop guard與TG報表；舊輪不回填成新版本績效。報表只核對verified市場的官方Shadow勝方，保留真正已驗證市場的身分／勝方衝突阻擋，未驗證時段不污染整輪Shadow。

Lane僅T6系列，T6.8排第一；有無安裝與有無選定／開跑須分別核對。切換版本不清HS、風控歷史、UNKNOWN、claim或交易紀錄。

## 驗證與推出

Reference價格／時段條件源於歷史探索；第180秒核心後樣本較少，獲利及fill提升尚未驗證。依使用者指示直接以原風控接入Live；以新輪的真實成交、費後PnL、MDD與拒絕原因評估。紙上quote不等於實際BUY，不把18+57宣稱為75%預期fill。

本PR不部署、不arm、不啟動loop。之後部署須沿用[安全操作限制](SECURITY_SCAN_20261002.md)，安全空檔、官方零曝險、完整VMinventory、STAGE外可信verifier與獨立核准fingerprint。備份／回復只涵蓋source、manifest與pin，不回復交易DB，不覆蓋其他人的新版本。
