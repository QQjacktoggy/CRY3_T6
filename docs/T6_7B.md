# T6.7b：保留策略，改善入場效率

Profile `regime_target6_7b_v1`，tier `REGIME_T67B`，package version `6.7.2`。
由已合併 PR9 的共用送單優化，加上已選中訊號的唯讀重檢組成。

## 策略與風控

延續 [T6.7a](T6_7A.md) 七條 Live：first DOWN、first UP、stall DOWN、
原 C DOWN、continuation Original、C-UP 前趨勢鏡像、淺回撤。
外部先行與 Reference 校正保留 Shadow。核心先凍結並保留資格，新分支
只在核心明確為空時參與。

價帶、凍結 cap、前趨勢、初始窗口、核心到期、新分支2秒TTL與金額規則
沿用原版；原 C DOWN 的 0.65 下限維持。共用 `regime_target6_risk_v1`
epoch、舊輪次結算、HS、UNKNOWN、固定20場MDD與整輪MDD持久停單均保留。
換版本不重設歷史風控，不自動解除HS、arm或建立新Live輪次。

## 入場更新

- 包含 PR9 的批次歷史風控讀取、避免重複市場登錄、原子 claim／intent／
  campaign、官方帳戶 GET 並行、transport 提交前時效及停單核對、批次診斷落盤。
- 首次凍結和選中仍在 SQLite writer transaction 中持久化，鎖定後再讀取，
  避免並行 caller 選到不同 signal。選中後，讀取 `t67b_decisions` 的唯讀連線
  不再取得 writer lock、呼叫 schema 初始化或提交 `last_evaluated_ms`。
- 每次重檢仍核對市場／loop／政策指紋／金額／費率、凍結 signal、最新盤口
  完整深度、新鮮度、價帶、凍結cap及到期。執行數量可依新盤口重算；凍結
  signal 不因新盤口更換，重啟後亦沿用持久signal。

這是減少同步成本的修正，不是放寬入場條件；離線測試不能保證正式 fill、
WR 或 PnL 增加。部署後應以候選→選中→intent→實際POST→fill分段觀測。

## 報表與版本隔離

T6.7b 使用獨立決策及Shadow tables、政策指紋、loop risk key。
Telegram可選T6.7b；選定後 `/report`、`/predict_report`、`/shadow_report`
顯示本版本輪的七路Live／兩路Shadow及子策略WR／PnL。尚未開跑時明示
尚無本輪資料，不回填T6.7a績效。Live官方結算與Shadow假設收益分開。
舊版資料與舊版報表保留，並納入共用歷史風控。

## 部署

先確認使用者已取消Loop或完整完成，沒有其他RUNNING Live輪次、UNKNOWN、
未終結intent／order，且官方掛單、持倉清空。核對正式父manifest／pin，
建立全inventory候選並在VM隔離測試；備份source、manifest／pin後才替換。
本版涉及worker、feature及signal的版本路由，安全空檔重新載入三個服務。
保留startup auto-arm／auto-start-loop=false。回復只回source及release資訊，
不回復交易DB。完成後使用者依原TG流程啟動新輪。
